## 1. 목표

핵심 목표는 "캐릭터 이입감"이며, 기술적으로는 아래 3가지를 안정적으로 만드는 것입니다.

- 기억의 연속성: 이전 대화가 다음 대화에 자연스럽게 이어진다.
- 관계의 변화감: 사용자 선택이 친밀도/신뢰도/서사에 실제로 반영된다.
- 캐릭터 일관성: MBTI 말투와 감정 표현이 흔들리지 않는다.

## 2. 현재 백엔드 기반(이미 구현됨)

- 채팅 API: `/api/v1/chat/send`, `/api/v1/chat/stream`
- 메모리 추출 API: `/api/v1/memory/extract`
- 일기 생성 API: `/api/v1/diary/generate`
- 파인튜닝 API: `/api/v1/finetune/start`, `/api/v1/finetune/status/{job_id}`, `/api/v1/finetune/activate`
- MBTI 페르소나 프롬프트 베이스: `app/prompts.py`
- 캐릭터별 파인튜닝 모델 라우팅 기반: `app/finetune_service.py`

## 3. 설계안

### 3.1 스토리 상태값 분리 저장

`room_id`(또는 `user_id + character_id`) 기준으로 아래 상태를 별도 저장합니다.

- `chapter`: 현재 서사 챕터
- `current_goal`: 캐릭터 또는 유저의 현재 목표
- `unresolved_hook`: 아직 회수되지 않은 떡밥
- `promise`: 대화에서 생긴 약속
- `trust_score`: 친밀도와 별개의 신뢰 점수
- `last_callback_at_turn`: 마지막 콜백 발생 턴

효과:
- 맥락 유지 비용 감소
- 프롬프트 길이 최적화
- 서사 진행의 체감 강화

### 3.2 3계층 메모리 구조

메모리를 아래 3개 레이어로 분리합니다.

- 프로필 사실(불변): 이름, 직업, 취향 등
- 감정/에피소드(중기): 싸움, 화해, 감동 같은 사건 기록
- 최근 대화(단기): 최근 N턴 컨텍스트

주입 우선순위:
1. 불변 프로필
2. unresolved_hook/promise
3. 관련 에피소드 Top-K
4. 최근 N턴

### 3.3 선택-결과 시스템

선택지를 고정 포맷으로 다루고, 결과를 상태값에 누적 반영합니다.

- 예시: 선택 A -> `affinity +1`, `trust +2`, `hook=데이트약속`
- 예시: 선택 B -> `affinity +2`, `trust -1`, `hook=오해`

반드시 다음 1~3턴 내 반영 규칙:
- 대사 톤 변화
- 회상/언급 변화
- 다음 목표 변화

### 3.4 야간 대화 종료 시 자동 일기

요구사항 반영 설계:
- 트리거 조건:
  - `end_of_session == true`
  - 사용자 로컬 시간 `22:00~04:59`
  - 캐릭터별 하루 1회 제한
- 생성 결과:
  - `diary_text`
  - `emotion`
  - `next_hook`(다음 만남 떡밥 1개)
  - `next_goal`(다음 만남 목표 1개)

저장 후 다음 세션 시작 시 `next_hook` 우선 소환.

### 3.5 콜백 규칙 엔진

N턴마다 과거 요소 1개를 재소환합니다.

- 콜백 후보: 약속, 별명, 미해결 사건, 감정 피크 이벤트
- 기본 규칙: 매 6~8턴마다 1회
- 반복 제한: 같은 콜백 2회 연속 금지

### 3.6 모델 라우팅(파인튜닝 포함)

모델 선택 우선순위:
1. `character_ft_model`
2. `mbti_ft_model`
3. 기본 모델(`gpt-4o`)

이렇게 하면 캐릭터 데이터가 적은 경우에도 MBTI 말투 일관성을 확보할 수 있습니다.

## 4. 우선순위 로드맵

## P0 (즉시, 1~2주)

1. 스토리 상태값 저장소 도입
2. 3계층 메모리 분리
3. 야간 자동 일기 + `next_hook`, `next_goal`
4. 콜백 규칙 엔진(기본형)
5. 운영 지표 수집(`D1`, 세션당 메시지 수, 콜백 적중률)

완료 기준:
- 대화 재진입 시 이전 목표/떡밥이 자동 반영
- 야간 종료 시 일기 1회 생성 및 저장
- 콜백이 규칙대로 발생

## P1 (단기, 2~4주)

1. 선택-결과 누적 시스템 고도화
2. MBTI별 파인튜닝 데이터셋 구축(JSONL)
3. MBTI 모델 매핑 및 라우팅 API 추가
4. 파인튜닝 실험/평가 자동화(`evaluate.py` 확장)

완료 기준:
- MBTI별 말투 일관성 점수 향상
- 선택 결과가 3턴 내 체감 가능

## P2 (중기, 4주+)

1. A/B 테스트 기반 서사 템플릿 최적화
2. 리텐션 기반 스토리 템플릿 추천
3. 이미지 연동은 후순위(텍스트 몰입 루프 안정화 후)

## 5. 파일 단위 구현 매핑(예정)

- `app/models.py`
  - `ChatRequest`에 `end_of_session`, `client_local_hour`, `room_id` 등 확장
  - `ChatResponse`에 `night_diary_generated`, `next_hook` 확장
- `app/main.py`
  - 채팅 종료 후 야간 조건 검사
  - 조건 만족 시 `generate_diary` 호출 및 저장
- `app/memory_service.py`
  - 3계층 메모리 API 분리
  - 콜백 후보 생성/조회 함수 추가
- `app/finetune_service.py`
  - `mbti_models.json` 관리
  - MBTI 모델 활성화/조회 함수 추가
- 신규 파일(권장)
  - `app/story_state_store.py`
  - `app/diary_store.py`
  - `app/metrics_service.py`

## 6. 파인튜닝 운영안(대시보드 + API)

학습 데이터 원칙:
- 최소 50~100 샘플/MBTI부터 시작
- 한 줄 1샘플 JSONL(chat messages 형식)
- 말투, 감정, 길이, 호칭 규칙이 드러나는 데이터 우선

배포 원칙:
1. 대시보드에서 Job 생성/모니터링
2. 완료 모델 ID를 등록
3. 캐릭터 또는 MBTI 라우팅에 연결
4. 품질 지표 비교 후 점진 배포

## 7. 운영 지표(초기 고정)

- D1 리텐션
- 세션당 메시지 수
- 콜백 적중률(의도한 콜백이 실제 응답에 반영된 비율)
- 야간 일기 생성률
- 일기 생성 후 다음날 재방문률

## 8. 최종 정리

현재 단계에서는 이미지/모션보다 아래 순서가 우선입니다.

1. 메모리와 스토리 상태 안정화
2. 야간 일기 + 떡밥 루프 완성
3. MBTI 파인튜닝으로 캐릭터 톤 고정

이 순서대로 가면 "이쁘다"보다 "계속 켜게 된다"를 먼저 만들 수 있습니다.
