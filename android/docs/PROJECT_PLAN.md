# MBTIChatFriend - 프로젝트 기획서

## 1. 프로젝트 개요

**앱 이름**: MBTI Chat Friend (가칭)
**컨셉**: 사용자가 선택한 MBTI 성격의 AI 캐릭터와 실제 채팅하듯 대화하는 미연시풍 채팅 앱
**핵심 가치**: 귀여운 캐릭터 + 자연스러운 대화 + 안전한 환경

---

## 2. 기술 스택

### Android (Frontend)
| 영역 | 기술 | 용도 |
|------|------|------|
| UI | Jetpack Compose + Material 3 | 모던 UI 구성 |
| 아키텍처 | MVVM + Clean Architecture | 유지보수성 |
| DI | Hilt | 의존성 주입 |
| 로컬DB | Room | 메시지 캐싱, 오프라인 지원 |
| 네트워크 | Retrofit + OkHttp | REST API 통신 |
| 실시간 | SSE (Server-Sent Events) | 메시지 분할 수신 (타이핑 효과) |
| 애니메이션 | Lottie / Compose Animation | 캐릭터 동작 표현 |
| 설정 저장 | DataStore | 사용자 설정, 토큰 저장 |
| 이미지 | Coil | 캐릭터 이미지 로딩/캐싱 |
| 네비게이션 | Navigation Compose | 화면 전환 |

### Python (Backend)
| 영역 | 기술 | 용도 |
|------|------|------|
| 프레임워크 | FastAPI | 고성능 비동기 API |
| LLM | OpenAI / Claude API | AI 대화 생성 |
| DB | PostgreSQL + SQLAlchemy | 유저/대화 데이터 |
| 캐시 | Redis | 세션, 대화 컨텍스트 캐시 |
| 인증 | JWT (PyJWT) | 사용자 인증 |
| 필터링 | 자체 룰 + LLM 기반 | 유해 콘텐츠 감지 |
| 배포 | Docker + Uvicorn | 컨테이너 배포 |

## 3. 핵심 기능 설계

### 3.1 온보딩 플로우
```
스플래시 → 로그인/회원가입 → 닉네임 입력 → 성별 선택 → 나이대 선택
→ 상대 MBTI 선택 → 캐릭터 선택 → 성향 설정 → 채팅 시작
```

**각 단계 상세**:
- **닉네임**: 2~8자, 금칙어 필터링, 중복 체크
- **성별**: 남성/여성/기타 (캐릭터 대화 톤 조절용)
- **나이대**: 10대/20대/30대/40대+ (콘텐츠 수위 조절)
- **MBTI 선택**: 16가지 MBTI 중 대화 상대 선택 (각 MBTI 특징 설명 포함)
- **캐릭터 선택**: MBTI별 기본 캐릭터 (외형 프리셋)
- **성향 설정**:
  - 말투: 존댓말 / 반말 / 츤데레 / 다정
  - 관계: 친구 / 연인 / 선후배
  - 관심사: 게임 / 음악 / 운동 / 독서 등 (복수 선택)

### 3.2 채팅 시스템

#### 메시지 분할 전송 (핵심 차별점)
AI 응답을 한 번에 보내지 않고 실제 사람이 채팅하듯 짧게 나눠서 전송:

```
[사용자] 오늘 뭐했어?

[AI - 0.5초 후] 오늘요?
[AI - 타이핑 중... 1초]
[AI - 1.5초 후] 카페에서 책 읽고 있었어요 ☕
[AI - 타이핑 중... 0.8초]
[AI - 2.3초 후] 요즘 추리소설에 빠졌거든요 📚
```

**구현 방식**:
- 서버에서 LLM 응답을 문장 단위로 분할
- SSE로 각 문장을 딜레이와 함께 순차 전송
- 클라이언트에서 타이핑 인디케이터 표시 후 메시지 표시
- 문장 길이에 비례한 자연스러운 딜레이 계산

#### 대화 컨텍스트 관리
- 최근 N개 메시지 컨텍스트 유지 (서버 Redis 캐시)
- 캐릭터 성격/설정 시스템 프롬프트 관리
- 호감도/관계 상태 반영
- 대화 주제 트래킹

### 3.3 캐릭터 시스템

#### 캐릭터 구성요소
```
캐릭터 = MBTI 성격 + 외형(일러스트) + 동작(애니메이션) + 음성톤(텍스트 스타일)
```

#### 감정 상태 시스템
| 감정 | 트리거 | 캐릭터 반응 |
|------|--------|------------|
| 기본(neutral) | 일반 대화 | 기본 포즈 |
| 기쁨(happy) | 칭찬, 공감 | 웃는 표정, 살짝 점프 |
| 수줍(shy) | 호감 표현, 고백 | 얼굴 붉힘, 시선 회피 |
| 슬픔(sad) | 슬픈 이야기, 이별 언급 | 고개 숙임, 눈물 |
| 화남(angry) | 무례한 말, 무시 | 뺨 부풀림, 팔짱 |
| 놀람(surprised) | 예상 못한 대화 | 눈 크게, 느낌표 |
| 애정(love) | 높은 호감도 + 달달한 대화 | 하트 이펙트, 미소 |

#### 호감도 시스템 (미연시 요소)
```
호감도 레벨:
Lv.1 낯선 사이 (0-20)    → 존댓말, 어색한 반응
Lv.2 아는 사이 (21-40)   → 약간 편한 말투
Lv.3 친한 친구 (41-60)   → 반말, 장난, 별명
Lv.4 특별한 사이 (61-80) → 다정한 표현, 걱정
Lv.5 연인 (81-100)       → 애칭, 스킨십 표현 (건전한 범위)
```

- 대화 내용/빈도에 따라 호감도 변동
- 호감도에 따라 캐릭터 말투/반응 변화
- 특정 호감도 달성 시 이벤트 대화 해금

### 3.4 캐릭터 동작 & 애니메이션

#### 채팅 화면 레이아웃
```
┌─────────────────────────┐
│  [←]  캐릭터이름  [≡]   │  ← 상단바 (뒤로가기, 메뉴)
├─────────────────────────┤
│                         │
│   ┌─────────────┐       │
│   │  캐릭터      │       │  ← 캐릭터 영역 (화면 상단 40%)
│   │  애니메이션   │       │     감정에 따라 동작 변화
│   │  (Lottie)   │       │
│   └─────────────┘       │
│                         │
├─────────────────────────┤
│  ┌──────────────┐       │
│  │ 안녕하세요!   │       │  ← 채팅 영역 (화면 하단 60%)
│  └──────────────┘       │     메시지 버블 + 스크롤
│       ┌──────────────┐  │
│       │  안녕! 반가워│  │
│       └──────────────┘  │
│  ┌──────────────┐       │
│  │ ● ● ●        │       │  ← 타이핑 인디케이터
│  └──────────────┘       │
├─────────────────────────┤
│  [📎] [메시지 입력...] [➤]│  ← 입력바
└─────────────────────────┘
```

#### 동작 트리거
- 메시지 수신 시 → 감정에 맞는 애니메이션 재생
- 타이핑 중 → 생각하는 포즈
- 대기 시 → idle 애니메이션 (숨쉬기, 깜빡임)
- 호감도 이벤트 → 특별 애니메이션

## 4. 보안 & 안전 설계

### 4.1 콘텐츠 필터링 시스템 (3단계)

#### 1단계: 클라이언트 사전 필터
- 입력 텍스트 기본 금칙어 체크 (로컬 사전)
- 의심 패턴 감지 (반복 특수문자, 우회 표현)
- 이미지 전송 시 기본 검증

#### 2단계: 서버 필터링
- **텍스트 필터**:
  - 금칙어 DB (정규식 + 유사어 매칭)
  - LLM 기반 맥락 분석 (우회 표현 탐지)
  - 성적/폭력/혐오 표현 분류 모델
- **이미지 필터**:
  - NSFW 이미지 감지 모델 (이미지 전송 기능 추가 시)
  - 이미지 메타데이터 검증
- **AI 응답 필터**:
  - LLM 출력에도 동일 필터 적용
  - 시스템 프롬프트에 안전 가이드라인 포함

#### 3단계: 제재 시스템
```
경고 1회 → 경고 메시지 표시
경고 2회 → 1시간 대화 제한
경고 3회 → 24시간 대화 제한
경고 5회 → 계정 정지 (수동 해제)
```

### 4.2 인증 & 보안
- **JWT 인증**: Access Token (15분) + Refresh Token (7일)
- **비밀번호 해싱**: bcrypt
- **API 통신**: HTTPS 필수 (TLS 1.3)
- **Rate Limiting**: 분당 30 메시지, 일일 500 메시지
- **입력 검증**: 모든 입력 서버사이드 검증, SQL Injection/XSS 방어
- **데이터 암호화**: 민감 정보 AES-256 암호화 저장
- **API 키 보호**: 서버 환경변수 관리, 클라이언트 노출 금지

### 4.3 예외처리 전략
| 상황 | 처리 |
|------|------|
| 네트워크 끊김 | 로컬 큐에 메시지 저장 → 재연결 시 전송 |
| 서버 오류 (5xx) | "잠시 후 다시 시도해주세요" + 자동 재시도 (3회) |
| AI 응답 실패 | 캐릭터성에 맞는 대체 응답 ("음... 잠깐 생각할게요!") |
| 필터 차단 | "이런 표현은 사용할 수 없어요" + 입력 초기화 |
| 토큰 만료 | 자동 Refresh → 실패 시 로그인 화면 |
| 앱 강제 종료 | 대화 상태 자동 저장 (Room) |

## 6. API 설계 (초안)

### 6.1 인증
```
POST   /api/v1/auth/register     # 회원가입
POST   /api/v1/auth/login        # 로그인
POST   /api/v1/auth/refresh      # 토큰 갱신
POST   /api/v1/auth/social       # 소셜 로그인
DELETE /api/v1/auth/withdraw      # 회원 탈퇴
```

### 6.2 사용자
```
GET    /api/v1/users/me           # 내 정보
PUT    /api/v1/users/me           # 정보 수정
POST   /api/v1/users/onboarding   # 온보딩 데이터 저장
```

### 6.3 캐릭터
```
GET    /api/v1/characters                    # 캐릭터 목록
GET    /api/v1/characters/{id}               # 캐릭터 상세
POST   /api/v1/characters                    # 캐릭터 생성 (커스텀)
GET    /api/v1/characters/{id}/affinity      # 호감도 조회
```

### 6.4 채팅
```
POST   /api/v1/chat/{character_id}/send      # 메시지 전송 (SSE 응답)
GET    /api/v1/chat/{character_id}/history    # 대화 히스토리
DELETE /api/v1/chat/{character_id}/history    # 대화 초기화
```

### 6.5 신고/필터
```
POST   /api/v1/reports                       # 신고 접수
GET    /api/v1/users/me/warnings             # 내 경고 이력
```

## 7. 데이터 모델

### 7.1 User (사용자)
```
id: UUID (PK)
email: String
nickname: String (2~8자)
gender: Enum (MALE, FEMALE, OTHER)
age_group: Enum (TEEN, TWENTIES, THIRTIES, FORTIES_PLUS)
profile_image_url: String?
created_at: DateTime
updated_at: DateTime
warning_count: Int (default 0)
is_active: Boolean (default true)
```

### 7.2 Character (캐릭터)
```
id: UUID (PK)
user_id: UUID (FK → User)
name: String
mbti: Enum (INTJ, INTP, ... 16종)
speech_style: Enum (FORMAL, CASUAL, TSUNDERE, SWEET)
relationship: Enum (FRIEND, LOVER, SENIOR_JUNIOR)
interests: List<String>
affinity_score: Int (0-100, default 0)
affinity_level: Int (1-5, default 1)
emotion_state: Enum (NEUTRAL, HAPPY, SHY, SAD, ANGRY, SURPRISED, LOVE)
image_preset: String
created_at: DateTime
```

### 7.3 Message (메시지)
```
id: UUID (PK)
character_id: UUID (FK → Character)
user_id: UUID (FK → User)
content: String
is_from_user: Boolean
emotion: String? (AI 메시지의 감정 태그)
created_at: DateTime
is_filtered: Boolean (default false)
```

### 7.4 Warning (경고 이력)
```
id: UUID (PK)
user_id: UUID (FK → User)
reason: String
original_message: String
severity: Enum (LOW, MEDIUM, HIGH)
created_at: DateTime
```

## 9. 추가 고려사항 (사용자 미언급분)

### 9.1 수익화 모델 (추후 검토)
- 기본 무료 + 프리미엄 구독 (추가 캐릭터, 무제한 대화)
- 캐릭터 외형 아이템 구매
- 광고 (비침습적, 배너 하단)

### 9.2 데이터 관리
- 대화 데이터 보관 기간 정책 (90일 기본)
- 사용자 데이터 삭제 요청 처리 (GDPR/개인정보보호법)
- 백업/복원 기능

### 9.3 접근성
- 다크 모드 지원
- 폰트 크기 조절
- 스크린 리더 지원 (contentDescription)
- 색약 모드 고려

### 9.4 분석 & 모니터링
- Firebase Analytics (사용자 행동 분석)
- Crashlytics (크래시 리포팅)
- 서버 모니터링 (Prometheus + Grafana)
- A/B 테스팅 (UI/대화 품질)

### 9.5 법적 고려

- 서비스 이용약관
