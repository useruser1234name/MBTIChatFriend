[10:10] ARCH-A 조성현 (선임 아키텍트):

캐릭터 편지는 '7일 이상 비접속 사용자'에게 발송됩니다.
현재 편지 생성 API는 On-demand (요청 시 생성)로 구현됐지만,
실제로는 배치 작업으로 매일 비접속 사용자를 스캔하고 편지를 생성해야 합니다.

제안 설계:
- 매일 00:00 UTC 스케줄러 실행 (APScheduler 또는 Celery Beat)
- 대상: last_active가 7일 이상 지난 opt-in 사용자
- 1인당 최대 1통 (30일 내 발송 이력 체크)
- 편지 생성: GPT-4o 호출 → letter_queue 테이블에 저장
- Android 알림 발송: FCM 통해 Push

이 스케줄러가 없으면 편지 기능 자체가 동작하지 않습니다.

둘째, LoRA 모델 서빙 통합:
FT 트랙에서 LoRA 체크포인트가 곧 나옵니다.
현재 서버는 OpenAI API만 사용합니다. LoRA 모델은 어떻게 서빙할 건지
아직 결정이 안 됐습니다.

옵션:
A. Hugging Face Inference API (유료, 쉬운 배포)
B. 자체 GPU 서버 (비용 높음, 제어 가능)
C. OpenAI Fine-tuning API (gpt-3.5-turbo 기반, 쉽지만 ENFP 특화 어려움)
D. vLLM 오픈소스 서빙 (경량 GPU 서버)"

근거 자료:
- APScheduler Python 라이브러리 공식 문서
- Hugging Face Inference Endpoints 가격 (2025 기준)
- vLLM: 고속 LLM 서빙 프레임워크 (Kwon et al., SOSP 2023)
