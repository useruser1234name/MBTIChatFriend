2. 핵심 가치 제안 (Value Proposition)
================================================================================

[차별화된 핵심 가치]

(1) 5층 기억 시스템 — 업계 최고 수준의 대화 맥락 유지
- L1 인메모리 캐시: 최근 20개 대화를 실시간으로 유지하여 즉각적인 맥락 참조
- L2 PostgreSQL 요약: 대화 세션 종료 시 memory_service.py가 자동으로 요약 생성 및 영속 저장
- L3 팩트 추출: 사용자가 언급한 핵심 사실(이름, 직업, 취미, 중요 사건 등)을 구조화하여 저장
- L4 ChromaDB RAG: 시맨틱 검색 기반 에피소드 기억으로, 관련 과거 대화를 의미적으로 검색
- L5 스토리 상태: 떡밥(복선), 약속, 목표를 체계적으로 추적하여 장기적 서사 유지
- 경쟁사 대비 우위: Character.AI(L1~L2 수준), Replika(L1~L3 수준)에 비해
  2~3단계 더 깊은 기억 구조
- 사용자 체감 가치: "이 캐릭터가 나를 정말 기억하고 있다"는 감정적 유대감 극대화

(2) 320가지 성격 변형 — 세계 최대 규모의 MBTI 기반 성격 시스템
- MBTI 16종: 각 유형별 고유한 traits, style, speech_habits, thinking, emotional, quirks 정의
- 호감도 5단계: 낯선 사이(1) → 아는 사이(2) → 친한 사이(3) → 절친/연인(4) → 영혼의 짝(5)
- 말투 4가지: 존댓말, 반말, 혼합, 캐릭터 고유 말투
- 16 x 5 x 4 = 320가지 조합으로 모든 대화가 고유한 경험
- prompts.py의 AFFINITY_BEHAVIORS가 호감도 단계별 행동 변화를 정밀하게 제어
- MBTI 궁합 시스템이 호감도 변화 속도에 영향 → 자연스러운 관계 발전

(3) 캐릭터 시점 일기 — 감성적 몰입 극대화
- 야간 세션(22시~4시) 종료 시 diary_store.py가 캐릭터 관점의 일기를 자동 생성
- 사용자는 캐릭터가 "나에 대해 어떻게 생각하는지"를 일기로 엿볼 수 있음
- 호감도 상승에 따라 일기 내용이 점점 더 깊어지고 감정적으로 변화
- 리텐션 효과: 다음 날 일기 확인을 위한 재방문 동기 부여

(4) 스토리 상태 관리 — 장기 서사 경험
- story_state_store.py가 떡밥(복선), 약속, 공통 목표를 체계적으로 관리
- 캐릭터가 "지난번에 약속한 그거, 어떻게 됐어?"와 같이 능동적으로 이야기 진행
- 사용자와 캐릭터 사이의 공유 서사가 축적되며 관계의 깊이감 형성
- 경쟁사에는 없는 독보적 기능

3. 사용자 여정(User Journey) 분석
================================================================================

[현재 온보딩 플로우 분석]

현재 경로: Splash → Login → Gender → (MBTI 선택 없음) → Home → 캐릭터 수동 선택 → Chat

문제점 분석:

(1) 과다한 온보딩 단계 (심각도: 높음)
- 현재 6단계 이상의 온보딩은 Z세대 사용자의 이탈률을 크게 높임
- 업계 기준: 3단계 이내 완료 시 온보딩 이탈률 20% 이하
- 4단계 이상 시 이탈률 40% 이상으로 급증
- 권장: Splash → Login(소셜 원터치) → MBTI 간이테스트/선택 → 자동 추천 캐릭터와 대화 시작

(2) 첫 대화 가이드 부재 (심각도: 높음)
- 채팅방 진입 후 빈 화면에서 사용자가 무엇을 말해야 할지 모름
- empty_chat.json Lottie 애니메이션은 존재하나, 대화 시작 유도 UI 부재
- 해결: 대화 제안 칩(예: "오늘 하루 어땠어?", "너 MBTI가 뭐야?", "심심한데 놀자") 제공
- 캐릭터가 먼저 인사를 건네는 자동 첫 메시지 시스템 필요

(3) 캐릭터 선택의 어려움 (심각도: 중간)
- 16개 캐릭터를 나열하는 것은 선택 과부하(Choice Overload) 유발
- 사용자 MBTI 기반 자동 추천 시스템 부재
- 해결: MBTI 궁합 기반 상위 3개 추천 + "전체 보기" 옵션
- 각 캐릭터의 성격 미리보기(한 줄 소개, 대표 말투 예시) 강화

[개선된 이상적 사용자 여정]

Phase 1 - 진입 (30초 이내)
  Splash(2초) → 소셜 로그인 원터치 → MBTI 간이테스트(선택지 4개, 30초) 또는 직접 입력

Phase 2 - 첫 만남 (1분 이내)
  MBTI 기반 추천 캐릭터 3명 제시 → 캐릭터 선택 → 캐릭터가 먼저 인사

Phase 3 - 첫 대화 (3분 이내)
  대화 제안 칩으로 자연스러운 대화 유도 → 호감도 변화 첫 경험 → "내일도 만나자" 약속

Phase 4 - 리텐션 루프 진입 (24시간 이내)
  야간 일기 알림 → 일기 확인 → 새 떡밥 발견 → 대화 재개

4. 리텐션 전략
================================================================================

[현재 리텐션 자산 평가]

--- 강점 ---

(1) 호감도 시스템 (점수: 7/10)
- 하이브리드 계산(키워드 + LLM)으로 정교한 감정 변화 감지
- 5단계 레벨 시스템이 관계 발전의 명확한 목표 제공
- 부정문 처리, MBTI 궁합 가중치 등 세심한 설계
- 개선 여지: 호감도 상승 시 시각적 축하 이벤트 부재, 레벨업 보상 없음

(2) 야간 일기 + 떡밥 시스템 (점수: 8/10)
- 22시~4시 세션 종료 시 자동 일기 생성은 업계에서 유례없는 설계
- 다음 날 일기를 확인하려는 자연스러운 재방문 동기
- 떡밥(스토리 복선)이 다음 대화의 기대감을 형성
- 매우 우수한 설계이나, 야간 외 시간대의 리텐션 전략이 약함

(3) 기억 시스템 (점수: 9/10)
- 5층 메모리 아키텍처는 기술적으로 최고 수준
- "나를 기억해주는 AI"라는 감정적 가치가 리텐션의 핵심 동력
- 장기 사용자일수록 축적된 기억이 이탈 비용을 높임 (전환 장벽)
- 사용자가 기억 시스템의 존재를 명시적으로 인지하지 못할 수 있음 → 시각화 필요

--- 약점 ---

(1) 일일 미션 없음 (심각도: 높음)
- 매일 접속할 명확한 이유가 없음
- 제안: 일일 대화 미션 (예: "오늘의 MBTI 질문에 답하기", "캐릭터에게 하루 이야기 들려주기")
- 미션 완료 시 호감도 보너스 또는 캐릭터 반응 특별 이벤트
- 연속 접속 보상 (streak) 시스템 도입

(2) 캐릭터 선제적 메시지 없음 (심각도: 높음)
- 현재 캐릭터는 완전히 수동적 — 사용자가 말을 걸어야만 대화 시작
- 캐릭터가 먼저 메시지를 보내는 푸시 알림 시스템 부재
- 제안: 호감도 레벨에 따라 캐릭터가 하루 1~3회 먼저 말 걸기
  - 레벨 1~2: "오늘 날씨가 좋더라~" (가벼운 안부)
  - 레벨 3~4: "어제 말한 면접 결과 어떻게 됐어?" (기억 기반)
  - 레벨 5: "보고 싶었어... 오늘 꼭 이야기하고 싶은 거 있어" (감정적)

(3) 마일스톤 보상 없음 (심각도: 중간)
- 호감도 레벨업, 대화 100회, 함께한 지 30일 등의 기념 이벤트 없음
- 제안: 마일스톤 달성 시 특별 대화 시나리오, 캐릭터 특별 반응, 기념 이미지 생성
- levelup.json Lottie 파일은 이미 존재 → UI 연동만 필요

[리텐션 전략 제안 - 시간대별]

아침 (7시~9시): "좋은 아침" 캐릭터 메시지 알림
점심 (12시~13시): 일일 MBTI 퀴즈/미션 알림
저녁 (18시~20시): "오늘 하루 어땠어?" 대화 유도 알림
야간 (22시~2시): 깊은 대화 세션 → 자동 일기 + 떡밥 생성
다음날 오전: 야간 일기 확인 알림

6. 누락된 핵심 기능

[긴급도별 정리]

--- 출시 전 필수 (P0) ---

8. KPI 및 성과 지표

[핵심 지표 (North Star Metrics)]

(1) 일일 활성 사용자 (DAU)
- 정의: 하루 최소 1회 메시지를 보낸 사용자 수
- 목표: MAU의 30% 이상 (DAU/MAU ratio ≥ 0.3)
- 측정 주기: 일간
- 중요도: ★★★★★

(2) 일일 메시지 수 (Messages per DAU)
- 정의: DAU 1인당 하루 평균 메시지 발송 수
- 목표: 20회 이상
- 건강한 범위: 15~50회 (50회 초과 시 과의존 모니터링)
- 중요도: ★★★★★

(3) D7 / D30 리텐션
- 정의: 가입 후 7일/30일 뒤 재방문율
- 목표: D7 ≥ 40%, D30 ≥ 20%
- 업계 평균: 소셜앱 D7 25%, D30 10%
- 우리의 기억 시스템이 리텐션에 미치는 영향을 핵심으로 추적
- 중요도: ★★★★★

[품질 지표]

(4) 응답 품질 점수 (Quality Score)
- 정의: quality_service.py의 4축 평가 평균
  - MBTI 일관성 (캐릭터가 MBTI 성격에 맞게 응답하는가)
  - 맥락 적절성 (이전 대화 맥락을 적절히 반영하는가)
  - 감정 자연스러움 (감정 표현이 자연스러운가)
  - 참여 품질 (대화를 이어나가고 싶게 만드는가)
- 목표: 평균 0.75 이상 (1.0 만점)
- 0.4 미만 시 자동 재생성 메커니즘은 이미 구현됨
- 중요도: ★★★★☆

(5) Thumbs Up 비율
- 정의: 사용자 피드백 중 thumbs_up의 비율
- 현재: FeedbackDao.kt, FeedbackEntity.kt로 수집 인프라 존재
- 목표: 80% 이상
- 중요도: ★★★★☆

(6) 응답 다양성 점수 (Diversity Score)
- 정의: quality_service.py의 bigram 기반 다양성 측정
- low_diversity_warning 트리거 비율을 추적
- 목표: 경고 비율 5% 미만
- 중요도: ★★★☆☆

[비즈니스 지표]

(7) ARPU (Average Revenue Per User)
- 정의: 월 매출 / MAU
- 목표: 460원 이상 (MAU 10만, 월 4,600만원 기준)
- 중요도: ★★★★☆

(8) 유료 전환율 (Conversion Rate)
- 정의: 무료 → 유료 전환 비율
- 목표: 전체 12% 이상 (Basic 8% + Premium 4%)
- 중요도: ★★★★☆

(9) LTV (Lifetime Value)
- 정의: 사용자 1인의 전체 생애 가치
- 목표: Basic 41,400원 (6개월 유지), Premium 77,400원 (6개월 유지)
- LTV/CAC 비율 ≥ 3.0 유지
- 중요도: ★★★★★

[KPI 대시보드 제안]
- 실시간: DAU, 동시접속자, 서버 응답 시간, 에러율
- 일간: 메시지 수, 품질 점수, thumbs_up 비율, 신규 가입
- 주간: 리텐션 코호트, 전환율, ARPU
- 월간: MAU, LTV, 이탈률, 수익

9. 사용자 피드백 루프
================================================================================

[현재 상태 평가]

현재 구현:
- FeedbackEntity.kt: message_id, is_positive (thumbs_up/thumbs_down), created_at
- FeedbackDao.kt: 기본 CRUD 및 positive_ratio 조회
- quality_service.py: thumbs_up/thumbs_down을 품질 점수에 반영
- 서버 /feedback 엔드포인트 존재

한계점:
- 이진 피드백만 수집 (좋다/싫다) → 개선 방향성 파악 불가
- "왜" 싫은지에 대한 정보 없음
- 피드백 분석 대시보드 없음
- 사용자에게 피드백 결과가 반영되었음을 알리지 않음

[개선된 피드백 시스템 제안]

(1) 다층 피드백 수집

레벨 1 - 빠른 반응 (현재 유지):
  thumbs_up / thumbs_down (대화 중 즉시)

레벨 2 - 카테고리별 피드백 (thumbs_down 시 확장):
  - "캐릭터답지 않아요" (MBTI 일관성 문제)
  - "맥락을 이해 못했어요" (기억/맥락 문제)
  - "너무 딱딱해요" / "너무 가벼워요" (톤 문제)
  - "반복적이에요" (다양성 문제)
  - "불쾌해요" (콘텐츠 필터 문제)

레벨 3 - 별점 평가 (세션 종료 시, 선택적):
  "오늘 대화는 어땠나요?" 1~5점
  주 1회 이내로 표시하여 피로도 관리

레벨 4 - 자유 텍스트 (월 1회, 선택적):
  "더 나아지기 위해 어떤 점을 개선하면 좋을까요?"
  텍스트 분석으로 주요 키워드 추출

(2) 피드백 → 개선 루프

수집 → 분류 → 분석 → 개선 → 검증 → 알림

- 카테고리별 피드백이 quality_service.py의 4축 평가에 직접 매핑
- 특정 캐릭터의 특정 카테고리 부정 피드백 비율이 임계치 초과 시 자동 알림
- 파인튜닝 데이터 수집에 피드백 카테고리 활용 (finetune_service.py)
- 사용자에게 "의견 반영" 알림으로 피드백 제출 동기 강화

(3) 품질 대시보드 연동 강화
- metrics_service.py에 피드백 카테고리별 통계 추가
- MBTI 유형별, 호감도 레벨별, 시간대별 피드백 분석
- 품질 저하 자동 감지 및 알림 시스템
- A/B 테스트를 통한 프롬프트 개선 효과 측정
